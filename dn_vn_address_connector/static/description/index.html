How the Connector Pack Works

Decoupled pipeline: External Open API v1 → Inbound Gateway Receiver → Transactional Queue → Optimized Safe Eval Handler.

1. Framework Preset

preset_vn_address_v1

Registers pre-tuned framework configuration with auth_type='none' or Bearer token, defining event paths and asynchronous deferred queuing.

2. Active Webhook Endpoint

vn-address-v1-inbound-token

Exposes dedicated route /connector/in/vn-address-v1-inbound-token capable of ingesting full national administrative trees in sub-50ms acknowledgments.

3. Zero N+1 Batch Handler

Dictionary Pre-Lookups

Pre-loads all existing provinces, districts, and wards into in-memory lookup maps, achieving bulk upsert speeds under 5 seconds for thousands of records.

OPTIMIZED INGESTION

Zero N+1 Query Optimization

Standard naive sync modules execute a search() query for every single ward, resulting in over 20,000 queries per sync. dn_vn_address_connector uses pre-mapped in-memory dictionaries:

# Pre-load state and district maps in memory state_by_code = { s.vn_code: s.id for s in env['res.country.state'].search([('country_id.code', '=', 'VN')]) } district_by_key = { (d.state_id.id, d.code): d.id for d in env['res.country.district'].search([]) } # Result: Bulk sync completes with only 3 SQL queries!
Transactional Safety: Sub-savepoints protect against corrupted rows.
