Engineered for Enterprise Integration

Built from the ground up to solve the architectural challenges of exposing Odoo to modern mobile apps, SPAs, and microservices.

Zero Sudo Bypass

Never compromises your ERP security. Every query and mutation executes strictly in the context of the authenticated service user, respecting Access Rights, Record Rules, and Multi-Company boundaries.

Atomic Savepoint Rollback

Guarantees all-or-nothing mutations. If any sub-operation fails inside a multi-mutation GraphQL payload, the entire PostgreSQL transaction rolls back cleanly, preventing partial or corrupted data.

Multi-Tier Deny Policies

Enforce granular field and model blocking at both Global and per-API Key levels. Block sensitive fields like passwords, hash tokens, cost prices, or internal notes before the query AST executes.

Dual Model Syntax

Supports both exact quoted Odoo names like "res.partner" and standard GraphQL sanitized identifiers like res__partner. No mental conversion needed when querying Odoo models.

Anti-Scraping Protection

Prevent denial-of-service and runaway queries. Built-in query depth limiting (max 6 levels), node count bounding (max 1000 nodes), and atomic per-minute rate limiting per API key.

Independent Audit Logging

Maintains an unalterable audit trail. Logs are written using an independent PostgreSQL cursor that persists execution timing, IP, user, and status codes even when mutations trigger rollbacks.

Engineering Architecture Breakdown

Handcrafted Custom Endpoints vs. Enterprise Dynamic Gateway Engine

Why hardcoding bespoke REST controllers leads to compounding technical debt and security vulnerabilities, and how our dynamic metadata-driven GraphQL engine solves API integration from first principles.

01

Zero-Code Model Exposure

Dynamic Schema Builder Engine
✕Handcrafted Custom Approach
Requires manually coding Python controllers, route handlers, serializers, and DTOs for every individual model. Adding 10 models requires hundreds of lines of fragile boilerplate code.
Enterprise Gateway Engine
Dynamic ORM introspection generates complete, type-safe GraphQL schemas on-the-fly for any standard or custom Odoo model with zero manual code writing.
02

Relay Cursor Pagination

Relay Cursor Resolver Engine
✕Handcrafted Custom Approach
Offset/Limit pagination leads to catastrophic O(N) database table scans on deep offsets and causes duplicate or missing records when rows are inserted or deleted during paging.
Enterprise Gateway Engine
Full Facebook Relay Cursor specification with edges, node, pageInfo, and opaque cursors. Delivers deterministic O(1) indexed lookups and seamless infinite scrolling.
03

Defense-in-Depth DoS Protection

AST Defense & Complexity Guard
✕Handcrafted Custom Approach
No query complexity analysis. Malicious or poorly designed nested queries can consume gigabytes of memory, exhaust Odoo workers, and crash the PostgreSQL backend.
Enterprise Gateway Engine
AST Query Depth Guard and maximum node ceiling inspect the GraphQL syntax tree before execution, instantly rejecting queries exceeding safety thresholds.
04

Atomic Sliding-Window Rate Limiting

Atomic Rate Limiter Subsystem
✕Handcrafted Custom Approach
In-memory rate limiters fail completely across multi-worker Odoo deployments, while external Redis setups require additional infrastructure, DevOps maintenance, and network roundtrips.
Enterprise Gateway Engine
PostgreSQL Atomic UPSERT (ON CONFLICT ... DO UPDATE) sliding-window algorithm guarantees strict, thread-safe rate limiting natively in PostgreSQL with zero external dependencies.
05

ACID Transactional Integrity

ACID Savepoint Controller
✕Handcrafted Custom Approach
Batch operations execute without coordinated transaction control. If mutation 3 of 4 fails, preceding records remain committed in the database, creating corrupted, partial-state data.
Enterprise Gateway Engine
Encapsulated in native PostgreSQL savepoints (cr.savepoint()). Any exception in any mutation triggers an immediate atomic rollback, preserving database consistency.
06

Immutable Audit Trail

Isolated Audit Trail Subsystem
✕Handcrafted Custom Approach
Logs are either dumped to unsearchable flat text files or stored in the database transaction, causing all audit records to be deleted when an error rolls back the transaction.
Enterprise Gateway Engine
Dedicated Isolated Database Cursor (registry.cursor()). Logs execution duration, client IP, key ID, node counts, and error tracebacks independently of transaction rollback.
07

Zero-Knowledge Key Storage & In-Place Rotation

Zero-Knowledge Key Storage Subsystem
✕Handcrafted Custom Approach
API keys are stored in plaintext in the database or hardcoded in configuration files. Rotating compromised keys requires manual database edits, code refactoring, or downtime.
Enterprise Gateway Engine
PBKDF2/SHA-512 salted cryptographic hashing, one-time reveal modal (transient store=False), and in-place rotateApiKey GraphQL mutation for zero-downtime key rotation.

Quickstart in 4 Easy Steps

Deploy your enterprise GraphQL Gateway in less than 5 minutes:

Step 1

Install Package

Install graphql-core >= 3.2.0 in your Odoo virtual environment:
pip install graphql-core

Step 2

Provision API Key

Go to GraphQL > API Keys. Create a dedicated key for your service user with scope graphql.

Step 3

Configure Models

Whitelist target models in Exposed Models and configure custom field deny policies under Blocklist Rules.

Step 4

Connect & Query

Send POST requests to /graphql with header Authorization: Bearer <key> and consume data smoothly.
