Zero Sudo Bypass

Never compromises your ERP security. Every query and mutation executes strictly in the context of the authenticated service user, respecting Access Rights, Record Rules, and Multi-Company boundaries.

Atomic Savepoint Rollback

Guarantees all-or-nothing mutations. If any sub-operation fails inside a multi-mutation GraphQL payload, the entire PostgreSQL transaction rolls back cleanly, preventing partial or corrupted data.

Multi-Tier Deny Policies

Enforce granular field and model blocking at both Global and per-API Key levels. Block sensitive fields like passwords, hash tokens, cost prices, or internal notes before the query AST executes.

Dual Model Syntax

Supports both exact quoted Odoo names like "res.partner" and standard GraphQL sanitized identifiers like res__partner. No mental conversion needed when querying Odoo models.

Anti-Scraping Protection

Prevent denial-of-service and runaway queries. Built-in query depth limiting (max 6 levels), node count bounding (max 1000 nodes), and atomic per-minute rate limiting per API key.

Independent Audit Logging

Maintains an unalterable audit trail. Logs are written using an independent PostgreSQL cursor that persists execution timing, IP, user, and status codes even when mutations trigger rollbacks.

GraphQL Query & Mutation Examples

Query any whitelisted Odoo model with intuitive Relay-style pagination, Odoo domains, and atomic mutations:

1. Quoted Model Query with Domain POST /graphql
query GetCustomers {
  "res.partner"(
    first: 10,
    domain: "[('is_company', '=', True)]",
    order: "name asc"
  ) {
    totalCount
    edges {
      node {
        id
        name
        email
        commercial_company_name
      }
    }
  }
}
2. Unquoted Relational Navigation Deep Many2one
query GetOrdersWithLines {
  sale__order(first: 5) {
    edges {
      node {
        name
        amount_total
        partner_id {
          name
          country_id { code name }
        }
      }
    }
  }
}

  }

Quickstart in 4 Easy Steps

Deploy your enterprise GraphQL Gateway in less than 5 minutes:

Step 1

Install Package

Install graphql-core >= 3.2.0 in your Odoo virtual environment:
pip install graphql-core

Step 2

Provision API Key

Go to GraphQL > API Keys. Create a dedicated key for your service user with scope graphql.

Step 3

Configure Models

Whitelist target models in Exposed Models and configure custom field deny policies under Blocklist Rules.

Step 4

Connect & Query

Send POST requests to /graphql with header Authorization: Bearer <key> and consume data smoothly.

Technical Specifications

  • Odoo Compatibility: Version 19.0 (Community & Enterprise)
  • Python Environment: Python 3.10, 3.11, 3.12+
  • Core Dependency: graphql-core >= 3.2.0
  • Transport Protocol: HTTP POST (JSON payload, UTF-8)
  • Authentication: Bearer API Key via res.users.apikeys

Security & Compliance Standards

  • No Sudo Policy: Standard Odoo ACL and Record Rules strictly enforced
  • Multi-Company: Transparent company isolation based on user context
  • Audit Trail: Independent PostgreSQL cursor preserves log history
  • Anti-Scraping: Enforces query depth, record count caps, and rate limits
  • Data Masking: Sensitive tokens and credentials masked in audit logs
