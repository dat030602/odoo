Dual-Engine Integration Framework

Unifies high-frequency incoming webhooks and scheduled outbound REST polling into a single, cohesive Odoo architectural layer.

Engine 1: Inbound API Gateway

High-Speed Asynchronous Webhooks
  • Fast HTTP Ingest: Dedicated /connector/in/<token> route returning 202 Ack in under 50ms.
  • Cryptographic Security: HMAC-SHA256, HMAC-SHA1, HMAC-SHA512 (Hex & Base64), Static Bearer & Basic Auth.
  • Transactional Inbox: Prevents data loss; persists raw JSON payload & headers prior to execution.
  • Idempotent Deduplication: Unique database constraint on (endpoint_id, idempotency_key) prevents duplicate records.
  • Circuit Breaker: Rejects excess backlog with HTTP 429 and Retry-After: 30 header under burst loads.
Ideal for Shopify, GitHub, Stripe, TikTok Shop, WooCommerce webhooks.

Engine 2: Outbound REST Poller

Automated Schema Discovery & Sync
  • Zero Registry Freeze: Dynamically provisions models, fields, and views without restart cycles.
  • Multi-Scheme Auth: Bearer Token, API Key header, HTTP Basic, and OAuth2 with automated refresh.
  • Universal Pagination: Supports Page Numbers, Offset/Limit, and Cursor-based token pagination.
  • Dynamic Schema Builder: Analyzes raw JSON responses, generating relational models and <list> views.
  • Delta Sync Engine: Incremental updates using external IDs with missing attribute logging.
Ideal for Open API v1/v2, ERP sync, CRM contacts, inventory pull.

HIGH-CONCURRENCY ARCHITECTURE

PostgreSQL SKIP LOCKED & Exponential Jitter

Standard Odoo cron workers often suffer from row contention and serialization failures when processing high-volume queues. dn_connector_base utilizes non-blocking PostgreSQL row locking:

  • Multi-Worker Claiming: Concurrent cron threads claim distinct batches without waiting or locking each other out.
  • Strict FIFO Ordering: When ordering_key == 'entity_id', subsequent messages wait until preceding records complete.
  • Exponential Backoff: Delay doubles per retry (10s, 20s, 40s...) plus randomized jitter to prevent thundering herd spikes.
# Inbound Processor Queue Claim Query query = SQL(""" SELECT id FROM connector_inbound_message WHERE state IN ('queued', 'failed') AND (next_retry_at IS NULL OR next_retry_at <= %s) ORDER BY priority DESC, received_at ASC, id ASC LIMIT %s FOR UPDATE SKIP LOCKED """, now, batch_size)
